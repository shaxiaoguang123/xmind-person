## 1. Parser Technology

**PASS.** Production `parseMarkdown.ts` composes `unified`, `remark-parse`, and `remark-gfm`. Section extraction recognizes mdast nodes by `node.type === 'heading'`. No source regex is used to implement Markdown heading parsing.

## 2. Duplicate Heading Identity

**PASS.** `duplicate-headings.md` produces two `API` sections. Unit coverage asserts distinct Node IDs and prevents title collision/overwrite.

## 3. Stable ID / Title Decoupling

**PASS.** Permanent Node IDs are opaque values generated by `crypto.randomUUID()` by default. They are not heading text, slug, or title hash.

A separate structural `projectionKey` is used only to look up a supplied prior mapping. The re-projection test changes both parent/child titles and bodies, injects the prior mapping, and uses an ID factory that throws if a new ID is requested. The test passes, proving identity reuse for the T01 supported boundary.

## 4. Local Body Ownership

**PASS.** Local Body is sliced from original source using root mdast node offsets after the section heading up to (but not including) the next root-level heading. Tests assert the `Word` parent body contains its paragraph/list but excludes both child heading text and child body text.

A long-body fixture also verifies later child content is not absorbed.

## 5. Setext Coverage

**PASS.** A real `setext-headings.md` fixture is parsed through remark/mdast and tests assert `Title` -> H1 and `Subtitle` -> H2.

## 6. Code Fence Safety

**PASS.** `code-fence-heading.md` contains `#` and `##` inside a fenced Markdown code block. Tests assert they are retained in Local Body but do not become Sections; only `Example` and `Real Heading` are extracted.

## 7. Skipped Heading Depth

**PASS.** `## A -> #### B -> ### C` preserves depths 2/4/3. The Section Tree makes B and C children of A and does not synthesize an H3 before B.

## 8. Preamble

**PASS.** Markdown before the first heading is preserved as document preamble. The synthetic document root remains separate from Markdown headings and can host documents whose first heading is not H1.

## 9. Source Position

**PASS.** Source positions come from mdast/unist `Position` values. `sourcePositions.ts` copies line/column/offset data and uses offsets to slice original Markdown. There is no custom line counter. Tests use those offsets to locate the original section source.

## 10. GFM Preservation

**PASS.** `remark-gfm` is enabled. Tests verify GFM AST node recognition and Local Body preservation for task-list syntax, strikethrough, autolink source, and table source while excluding the child section.

## 11. Empty / Duplicate / Unusual Valid Markdown

**PASS.** Empty sections, duplicate headings, skipped depth, Chinese headings, Setext headings, and first-heading-not-H1 are treated as valid Markdown rather than application errors.

## 12. Error Boundary

**PASS.** `MarkdownCoreError` distinguishes invalid application/runtime assumptions (for example missing required AST offsets, duplicate supplied stable IDs, empty IDs, unavailable opaque ID generation) from valid unusual Markdown.

A first CI run exposed a TypeScript model mismatch between a local position type and unist `Position`. The fix replaced the redundant type with the real unist types; strict TypeScript settings and test assertions were not weakened.
